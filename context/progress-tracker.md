- `context/current-issues.md` bug fix: dialog titles (and, latently, every other `text-base` usage — `components/ui/card.tsx` titles, `components/ui/input.tsx`, `components/ui/textarea.tsx`) rendered near-black instead of `text-copy-primary`. Root cause: `app/globals.css` registered `--color-base: var(--bg-base)` in `@theme inline` purely to get a `bg-base` utility for the page background, but Tailwind v4 auto-generates a same-named color utility for *every* class suffix from a `--color-*` token — so it silently redefined the built-in `text-base` font-size utility as `color: var(--bg-base)` (near-black) instead. Fixed by dropping `--color-base` from the theme block and hand-defining `@utility bg-base { background-color: var(--bg-base); }` instead, so `bg-base` still works per `context/ui-context.md` without clobbering `text-base`/`border-base`. Verified via a temporary public `/dev-preview` route (removed after) rendering `ProjectDialogs` and a Playwright screenshot/computed-style check confirming `dialog-title` now resolves to `rgb(240,240,244)` at 16px; `tsc --noEmit`, `eslint .`, `next build` all clean.
- `context/current-issues.md` bug fix (round 2): `submitCreate`/`submitRename` in `hooks/use-project-dialogs.ts` only checked `name.trim()`, so a name like `"!!!"` (no letters/digits) passed validation but `slugify()` collapsed it to an empty string, storing a project with `slug: ""`. Fixed by deriving `slug = slugify(name)` in both submit functions and guarding on `!slug` too, not just `!name.trim()`. `components/projects/project-dialogs.tsx` now surfaces the same distinction in the UI for both Create and Rename: the confirm button is disabled whenever the name is empty *or* the derived slug is empty, and the helper text under the input switches between "Enter a name to preview the slug" / "Name must include at least one letter or number" (shown in `text-error`) / the live `/slug` preview. Verified with the same temporary `/dev-preview` route + Playwright: typing `"!!!"` shows the red validation message and leaves the confirm button `disabled`; `tsc --noEmit`, `eslint .`, `next build` all clean.
